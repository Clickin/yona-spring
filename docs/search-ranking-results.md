# #843 검색 순위 개선 실측

실측 결과를 반영해 **1단계는 되돌리고, 근접도 설정을 변경하고, 식별자 경계 처리는 유지했다.** 앞선 환경변수 미설정에 따른 미측정 기록을 이 문서로 대체한다.

- 브랜치: `poc/issue-843-search-ranking`. push하지 않았다.
- 기준선: `1a85fc396`.
- 최초 구현 커밋: 1단계 `9644755c3`, 2단계 `ac9e01de7`, 3단계 `c4e414bed`. 이 세 커밋만으로는 최종 실측 설정이 아니다.
- 최종 설정: 기준선의 0점 보조 경로 + 근접도 B + 식별자 경계 수정(VERSION 3).
- 기본 `yona.search.backend=db`, DB 검색, 의존성은 변경하지 않았다.
- 전체 집계와 단계별·유형별 수치는 [search-ranking-results.json](search-ranking-results.json)에 있다. 검색어 원문과 개별 결과는 없다.

## 환경과 재현성

평가 데이터를 읽기 전용 입력으로 사용했다. 이슈 4,882건·댓글 6,335건, JDK 21.0.6, 최대 heap 1 GiB, MariaDB 10.11, `utf8mb4_unicode_ci`, 관리자 권한이다. 실행마다 새 컨테이너·빈 DB·새 출력 디렉터리·새 JVM을 사용했다. 실행은 순차이며 동시 측정하지 않았다.

seed 843은 3,371개 유효 검색어와 missing 20개, seed 844는 3,392개 유효 검색어와 missing 20개다. 각 seed의 비교 대상에서 `(유형, 원래 이슈, 검색어)`가 모두 동일했다. seed 843 기준선의 모든 유형별 품질·결과 건수 지표와 색인 bytes는 docs 브랜치의 기존 `identifierAfter` 기록과 정확히 일치했다.

측정 도구는 docs 브랜치의 `IssueSearchQualityProbe.kt`와 `resource-probe.gradle`을 사용했다. 페이지 호출 1회 예열 후 3회 중앙값, 그 값의 p50/p95를 기록한다. HTTP·화면 렌더링·동시 부하는 포함하지 않는다. 순위 비교를 위해 비공개 검색어별 출력에 Lucene 전체 ID 순서와 Nori ID 순서만 추가했다. 이 추가 출력은 시간 측정 뒤에 기록하며 검색어 생성·검색·시간 측정 방식은 바꾸지 않았다.

실행 순서: 기준선 843 → 1단계 843 → 근접도 A 843 → 근접도 B 843 → 근접도 B 844 → 기준선 844 → 최종 843. seed 844 결과를 보고 설정을 다시 튜닝하지 않았다.

## 단계별 판단

### 1단계: 보조 BM25 — 되돌림

- 전체 MRR: 0.375937→0.375812. 상위 5건: 47.878968→47.730644%. 상위 10·20건은 소폭 올랐지만 주 지표 MRR과 상위 5건이 낮아져 유지하지 않았다.
- camel 뒷부분 MRR은 0.378838→0.377729, 앞부분은 0.464069→0.463775로 낮아졌다.
- Nori 문서의 순위 하락은 전체 검색어에서 **0건**이다. 원래 이슈만이 아니라 Nori 일치 문서 전체의 위치를 비교했다. 일치 집합 변화와 찾던 정답의 누락도 0건이다.
- 두 번 검색하는 구현, 단계 기반 `auxiliaryOnly`, 해당 BM25 순서 테스트를 제거하고 기준선의 합성 쿼리·0점 보조 경로·점수 기반 보조 판별로 복원했다. 기존 스니펫 생략을 유지한다. 스니펫의 `QueryScorer`는 Nori 필드(`title`, `body`, `comments`)만 대상으로 하므로 식별자 보조 필드는 강조하지 않는다.

### 2단계: 근접도 — B 선정

기존 필수 조건은 MUST, 따옴표 밖 전체 문자열의 구문만 SHOULD다. 분석 토큰 2개 미만이면 추가하지 않는다. 1단계는 제외한 상태에서 정확히 두 설정을 비교했다. 가중치는 기존 필드 가중치에 곱한다.

| 설정 | slop 0 가중치 | 가까운 구문 slop / 가중치 | seed 843 전체 MRR | exact MRR |
|---|---:|---|---:|---:|
| 기준선 | 없음 | 없음 | 0.375937 | 0.341329 |
| A (최초 구현) | 3 | 4 / 1 | 0.441958 | 0.483334 |
| **B (선정)** | **5** | **3 / 1** | **0.449125** | **0.500497** |

두 설정 모두 seed 843에서 일치 문서 집합 변화 **0건**, 찾던 정답 누락 **0건**이다. B는 모든 유형의 MRR이 기준선 이상이다. A보다 separated·reordered의 MRR은 낮지만 전체·exact에서 B가 더 좋아 선정했다.

seed 844에서도 B의 전체 MRR **0.366480→0.461056**, exact **0.285912→0.551854**, 상위 20건 **66.303066→72.995283%**로 개선됐다. 일치 집합 변화와 찾던 정답 누락은 **0건**, 유형별 MRR 하락도 없다. 다른 seed에서도 개선 방향은 유지됐지만 동일 archive에서 뽑은 표본이므로 독립 데이터셋 일반화를 입증하지는 않는다.

순위 변경에는 개별 하락도 있다. B 적용으로 Nori에서 찾던 원래 이슈의 순위가 내려간 검색어는 seed 843에서 189건, seed 844에서 165건이다. 0건 요구는 1단계에만 적용되며, 2단계는 일치 집합을 유지하면서 전체 순위 지표를 개선한다.

### 3단계: 약어·한글 경계 — 유지

- `PatternReplaceCharFilter`의 약어 경계 분리, ASCII 영문·숫자 및 `._/-`만 허용하는 `CharTokenizer`, 같은 경계에 맞춘 검색어 정규식을 사용한다. 색인과 검색어에 같은 분석기를 적용한다.
- VERSION은 3이며 구버전 색인의 전체 재생성과 실패 롤백을 유지한다.
- 기존 식별자 실패 **57건 모두 해결**, 추가 식별자 1,640건의 찾은 비율 **100%**다. 앞서 분류한 약어 경계 **50→0건**, 한글 인접 **7→0건**에 해당한다. 이번에는 분류를 다시 추정하지 않고 기존 57건 전체의 해결 여부를 대조했다.
- 근접도 B 대비 일치 집합이 바뀐 검색어는 156개, 기존 정답 누락 0개다. Nori 문서 순위 하락도 0건이다.
- 전체 MRR 0.449125→0.456700, 상위 20건 71.729457→73.064373%, 찾은 비율 96.143578→97.834470%로 개선됐다.
- 모든 유형의 MRR이 근접도 B 이상이며 전체 순위·재현율이 개선돼 유지했다.

최종 H2 회귀 **507개 통과**, 실패·오류·건너뜀 0. 기존 505개에 근접도와 경계 회귀 2개가 남는다. 최초 508개에서 되돌린 보조 BM25 테스트 1개를 제거했다. 데이터 복원·큐 색인·서비스 페이지 호출은 위 7회의 측정으로 확인했고, 최종 소스는 마지막 측정에 사용한 소스와 동일하다.

## 재현

측정 문서와 원본 도구는 `docs/issue-843-lucene-poc`에 있다. 이 문서의 구현 브랜치와 이력을 합치지 않는다.

```sh
git worktree add --detach /tmp/yona-ranking-probe poc/issue-843-search-ranking
git -C /tmp/yona-ranking-probe restore --source=docs/issue-843-lucene-poc --worktree -- \
  src/test/kotlin/com/github/yonaprojects/yona/domain/issue/IssueSearchQualityProbe.kt \
  support-script/search-poc/resource-probe.gradle
# YONA_PROBE_ARCHIVE: 평가 입력 archive의 절대 경로
# YONA_PROBE_JDBC: 별도 MariaDB 10.11의 빈 DB
# YONA_PROBE_DB_PASSWORD: 해당 임시 DB의 비밀번호
# YONA_PROBE_OUTPUT: worktree 밖의 아직 없는 출력 디렉터리
# YONA_PROBE_SAMPLE=300, YONA_PROBE_SEED=843 또는 844
# YONA_PROBE_CASES_OUTPUT: 선택 사항. worktree 밖 비공개 경로만 사용

  --init-script /tmp/yona-ranking-probe/support-script/search-poc/resource-probe.gradle
```

H2 대상과 init script는 docs 브랜치 `docs/search-poc.md`의 검증 절을 따른다. 검색어 원문·개별 결과·비밀번호는 커밋하지 않는다. 각 실행 종료 시 측정 컨테이너·볼륨과 임시 복원 데이터·색인을 삭제했다. 평가 입력은 변경하지 않았다.

## 다음 실험 우선순위

아래 항목은 구현하지 않았다. 효과는 아직 가설이다.

1. **식별자 일치를 Nori 결과의 점수에 반영**: 식별자 재현율은 100%가 됐으므로 다음은 이미 찾는 결과의 순위 개선이다. 단순 보조 BM25가 효과 없었던 점을 반영한다.
2. **NNB·VX 선택 조건 완화**: 남은 한국어 73건의 품사 원인을 분류한 뒤 제한적으로 실험한다.
3. **minimumShouldMatch 완화**: 일부 토큰으로 인한 누락에 대응하되 결과 확대·정밀도 저하를 함께 확인한다.
4. **한글 bigram 보조 필드**: Nori 분석 경계 실패의 대안이나 색인·오탐 비용이 추가된다.
5. **BM25 k1·b**: 빈도·문서 길이가 순위 문제의 원인이라는 근거가 생기면 시도한다.
