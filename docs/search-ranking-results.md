# #843 검색 순위 개선

기준선: `1a85fc396`, 표본 기준: docs/issue-843-lucene-poc의 `identifierAfter` (seed 843).
기본 DB 검색과 `yona.search.backend=db`는 변경하지 않는다.

## 측정 환경

`YONA_PROBE_ARCHIVE`, `YONA_PROBE_JDBC`, `YONA_PROBE_DB_PASSWORD`, `YONA_PROBE_OUTPUT`이 모두 없어 실제 데이터 품질 측정은 실행하지 않았다. 대체 데이터로 품질 수치를 만들지 않았다. 측정 도구는 docs 브랜치에서 복원했지만 커밋하지 않는다. 컨테이너나 archive 복원본은 생성하지 않았고 평가 입력은 건드리지 않았다.

기준선 전체: MRR 0.375937, 상위 5/10/20건 47.878968% / 56.748739% / 66.004153%, 찾은 비율 96.143578%, 결과 건수 p50/p90 21/448, 첫 페이지 p50/p95 10.586375/42.350834ms, 색인 8,375,012 bytes. exact MRR은 0.341329 (LIKE 0.661872).

## 1단계: 보조 결과 BM25

- Nori 검색 후 Nori 일치를 제외한 보조 검색을 실행하여 이어 붙인다. 보조 결과끼리는 자체 BM25 순서를 따른다.
- `auxiliaryOnly`는 점수가 아니라 검색 단계로 결정한다. `query()`는 Nori 쿼리만 반환하며 기존 스니펫 생략 처리는 유지한다.
- H2 회귀 506개 통과(기존 505개와 신규 1개), 실패·오류·건너뜀 0. 기존 Nori 점수와 순서 보존도 검증했다.
- 별도 JVM에서 실제 디스크 색인·검색 실행: Nori ID 3 다음 보조 ID 2, 1 및 단계 플래그 확인.
- 실제 표본의 Nori 순위 하락 건수와 모든 품질·성능 지표는 미측정. 효과 없음 또는 악화를 판정할 근거가 없어 되돌리지 않았다.

## 2단계: Nori 근접도

- 기존 필수 쿼리를 MUST로 유지하고 따옴표 밖 전체 텍스트의 구문을 SHOULD로 추가했다. slop 0은 필드 가중치의 3배, slop 4는 1배다. 분석 토큰이 2개 미만이면 추가하지 않는다.
- H2 회귀 507개 통과, 실패·오류·건너뜀 0. 인접 구문 우선, 떨어진 단어·다른 필드·댓글 간 일치 유지, 따옴표 제약과 단일 토큰 검색을 확인했다. 1단계의 이전 BM25 점수 비교는 이 단계에서 의도적으로 순위를 바꾸므로 Nori 결과 집합과 보조 결과 후순위 검증으로 바꿨다.
- 별도 JVM 디스크 색인·검색에서도 인접 문서 우선과 떨어진 단어·다른 필드의 결과 보존을 확인했다.
- 이 설정은 실측으로 선정한 값이 아니다. 환경 미비로 후보 2~3개 비교와 seed 843/844 재검증을 실행하지 않았다. 실제 표본의 전체·유형별 지표, 일치 집합 비교와 과적합 여부는 미확인이다.
- 품질 악화나 무효를 판정할 측정값이 없어 되돌리지 않았다.

## 3단계: 식별자 경계

- `PatternReplaceCharFilter`로 약어 끝과 다음 단어 사이를 나누고, ASCII 영문·숫자와 `._/-`만 허용하는 `CharTokenizer`로 한글 경계를 나눈다. 검색어 `IDENTIFIER`도 한글에 붙은 ASCII 식별자를 추출하도록 맞췄다.
- 색인과 검색어에 같은 분석기를 적용하고 VERSION을 2에서 3으로 올렸다. 버전 없음·1·2의 색인 재생성과 실패 롤백·재시작을 검증했다.
- H2 회귀 508개 통과, 실패·오류·건너뜀 0. 약어의 앞부분·뒷부분·전체, 한글에 붙은 식별자 및 혼합 검색어, 구문·댓글 경계 보존을 검증했다.
- 별도 JVM 디스크 색인·검색에서도 약어와 한글 경계 검색을 확인했다. 실행용 임시 소스와 스크립트는 검증 후 삭제했다.
- 실제 실패 표본의 약어 50건·한글 인접 7건 중 해결 건수는 미측정이다. 회귀 예제 통과를 실제 57건 해결로 환산하지 않는다. 품질을 근거로 되돌린 단계는 없다.

## 후속 우선순위 의견

아래는 구현하지 않았으며 효과는 실측 전 가설이다. 먼저 이번 변경을 실제 데이터로 측정하고 2단계 후보를 seed 843/844에서 검증한다.

1. 식별자 일치를 Nori 결과의 점수에 반영: 이미 찾은 식별자 검색의 순위를 직접 개선할 후보. Nori 순위 보존 정책과는 별도 실험이다.
2. NNB·VX 선택 조건 완화: 한국어의 남은 실패를 품사별로 확인한 뒤 제한적으로 실험한다.
3. `minimumShouldMatch` 완화: 일부 토큰이 원인을 제공하는 실패에 효과가 있을 수 있으나 결과 확대를 함께 재야 한다.
4. 한글 bigram 보조 필드: 분석 경계 실패의 대안이나 색인 크기와 오탐 비용이 추가된다.
5. BM25 `k1`·`b`: 단어 빈도·문서 길이에 의한 순위 문제라는 근거가 생기면 시도한다.
