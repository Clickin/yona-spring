# SPEC-CHANGE-003 — bounded nonblocking SSE transport

**Status:** additive contract proposal; not approved, implemented, or product-runtime-verified. The parent ran an isolated Tomcat adapter prototype, documented below; no Yona endpoint/actual-topology acceptance is claimed. The amendment changes the SSE transport mechanism, not its externally visible protocol, authorization, quotas, convergence, privacy, or timing criteria. Frozen inputs are unchanged. The amended copies in this directory are based on the frozen SSE protocol and the latest `rest-amendment/functional-spec.md` and `api-openapi.yaml` copies.

## Decision

Replace the frozen blocking `SseEmitter` plus dedicated 32-thread writer pool with exact-route Servlet nonblocking output and a request-scoped, connection-bound abort capability. An external watchdog invokes Tomcat's normal `ERROR,false` processing path on the captured `SocketWrapperBase`; never store a Servlet/Coyote `Response`, invoke raw `CLOSE_NOW`, or directly close the wrapper. Do not treat Spring MVC async completion, interruption, emitter-pool bounds, connector idle timeouts, or proxy `send_timeout` as a stalled-write abort guarantee.

The exact candidate stack is Spring Boot 4.1.1 / Spring Framework 7.0.9 / Tomcat 11.0.24 / Servlet 6.1 / Java 21. Boot's stock backend is HTTP/1.1 NIO; a tiny instrumented protocol/processor subclass captures only the live connection wrapper and leaves Tomcat I/O, timeout, TLS, and upgrade behavior unchanged. This Tomcat-specific implementation is not a portable Servlet promise.

## Preserved external contract

No client-visible SSE semantics change:

- Same-origin session-cookie GET at the context-relative `/api/admin/queue/v1/events`; current DB-backed site-manager authorization, full-authentication requirement, Pre2fa denial, JSON `401`/`403`, no login redirect, no personal-token authorization, no CORS, and no CSRF requirement for read-only GET remain.
- Eligible responses retain `text/event-stream;charset=UTF-8`, no-cache, proxy-buffer suppression where supported, no fixed content length, and no whole-response buffering. The successful HTTP/1.1 SSE response sets `Connection: close` so the connection-bound abort handle cannot affect a later request on the same socket; this header is only on `/events`. `reset`, `changed`, heartbeat comments, `Last-Event-ID` acceptance/no replay requirement, REST refetch convergence, and privacy rules remain unchanged.
- Preserve at most 32 active streams per application instance, 2 per principal, 2 per session; one shared application generation poll at 1 Hz; shared distinct-principal and distinct-session authorization schedules at 1 Hz; no connection-owned DB connection/transaction; one coalesced pending frame per stream; and heartbeat no less frequently than every 15 seconds while idle.
- A committed generation change still fans out within 2 seconds on a healthy stream. Slow/disconnected clients do not backpressure a worker or transaction; drop/coalesce invalidations and converge through `reset` plus REST.
- Failed authority/session checks stop sensitive writes immediately, discard pending frames, and physically close the corresponding server connection within 5 seconds of revocation becoming visible to the application. No application frame may be written after a check fails.

## Bounded producer and transport seam

Use one package-internal stream handle, not a public API or general event framework. Its operations are limited to offering typed `reset`, `changed(generation)`, and `heartbeat` frames and closing the stream. It owns at most one coalesced pending frame per stream. A newer `changed` replaces/coalesces the older invalidation; overflow becomes `reset`. Frames are protocol-bounded and encoded once. It has no arbitrary byte-write operation for production producers.

Register this single endpoint as an async-supported native Servlet at the exact context-relative events mapping (Spring Boot `ServletRegistrationBean`) rather than routing it through Spring MVC emitter/streaming async wrappers. The existing Spring Security filter chain and current authentication/authorization checks still apply. This is one endpoint seam, not a second API or application framework.

Use a small instrumented `QueueSseHttp11NioProtocol` subclass that creates a `QueueSseHttp11Processor` subclass. The processor overrides only `service(SocketWrapperBase<?>)`: set a non-inheritable ThreadLocal to that live wrapper around `super.service()`, then restore/remove it in `finally`. The exact-route Valve reads that current wrapper only while servicing `/events` and attaches a request-scoped handle; the Valve does not authorize. No wrapper or response is stored globally. The subclasses do not override socket I/O, timeouts, TLS, or upgrade behavior.

The stream's `WriteListener` callback checks `isReady()` before every bounded write, writes only a bounded chunk, and returns without spinning when not ready. It never waits for readiness, retries in a loop, or executes an abort loop in a Tomcat callback. Any callback-side failure only marks the connection terminal/pending-abort. A shared bounded watchdog processes pending aborts only from an external non-container thread after the current socket callback unwinds; no unbounded executor backlog or caller-runs path is allowed. No 32-thread application writer pool or per-stream thread is retained.

A test-profile-only control may arm one already-authenticated real queue stream with a finite pressure budget (maximum 64 MiB attempted bytes). It emits reusable valid SSE comment chunks of at most 4 KiB each through the same production offer/pending/write/readiness/abort path. It cannot invent `changed` events, mutate generations, enqueue jobs, bypass stream caps, or write through a second endpoint. Keep the next chunk pending while the current chunk is in flight so one continuous pressure episode preserves its oldest age across readiness pulses. It is disabled outside the test profile and is not part of the production stream handle.

## Absolute age, abort, and close serialization
For each stream, set `outstandingSince` from a monotonic clock when its application output episode first becomes pending, before attempting the first Servlet write. Keep that oldest age across partial writes, readiness/progress callbacks, coalescing, replacement, and newly offered frames while an in-flight or pending frame remains. Outstanding includes application/Servlet pending bytes, partial writes, and Tomcat HTTP/1.1 connector output buffers. The external watchdog starts normal `ERROR,false` processing by `outstandingSince + 1.5s` at latest; the **actual server connection must be closed by `outstandingSince + 2.0s`**. This gate includes watchdog scheduling, wrapper-lock wait, error dispatch, async accounting, and physical close.

The only clear condition is an atomic idle-and-drained transition under the per-stream lock: the in-flight frame is fully submitted and successfully flushed; no application/Servlet bytes or pending frame remain; and a live native nonblocking `WriteListener` is still installed. In that serialized state, call public `ServletOutputStream.isReady()` after flush, either from the current `onWritePossible()` callback or from the normal writer path; `true` on pinned Tomcat HTTP/1.1 NIO reaches the `!hasDataToWrite()` predicate and means Tomcat's main/nonblocking output buffers are empty. Do not require a new callback when the stream is already ready. This does **not** observe the OS TCP send queue, peer ACK, or client receipt. Tomcat's TLS source also checks outbound TLS buffers, but direct secure connectors are runtime-ineligible and external proxy/TLS buffers remain a topology release gate. A readiness/progress pulse cannot clear age while an in-flight or pending app frame remains; if a new frame is offered before this atomic idle-and-drained transition, retain the same age. Only a later frame after that transition starts a new episode. Use the live Servlet readiness API, not raw `NB_WRITE_INTEREST` polling, Valve/private-field introspection, or synthetic/re-registered callbacks. This premise requires successful flush, no upper response wrapper/compression layer that buffers unobserved bytes, an active listener, no concurrent write/abort race, and the pinned Tomcat implementation. If any premise is unproven, that route is ineligible.
The captured `SocketWrapperBase.getLock()` is the stream's write/abort serialization gate and the same `ReentrantLock` used by `SocketProcessorBase`. Every bounded readiness/write and abort-state transition uses it; no DB or blocking IO runs under the lock. Any cause marks the stream terminal, clears pending data, and sets one-shot `pendingAbort`. A shared bounded watchdog runs off every Tomcat callback, acquires the wrapper lock after the current socket processor unwinds, claims the abort once, then releases all wrapper/stream/registry locks before calling `wrapper.setError(IOException)` and `wrapper.processSocket(SocketEvent.ERROR, false)`. Include wrapper-lock wait and full ERROR/close processing in the 2-second budget. Never invoke ERROR,false or wrapper.close inline from `service`, Valve, WriteListener, AsyncListener, or a nested callback: SocketProcessorBase's reentrant lock/current processor could be recycled before the outer service returns. No raw Response or direct close is permitted.
The normal `ERROR,false` Coyote path invokes its internal `CLOSE_NOW`, dispatches the async error, and performs async post-processing/connection cleanup. Only `AsyncListener.onError`, after IO is forbidden, performs bounded cleanup and calls that event's `AsyncContext.complete()` to finish async accounting and avoid a blocking default error-page flush. This is error finalization, not the abort mechanism or graceful-completion fallback. `WriteListener.onError` occurs before the Coyote close action and only marks/cleans state; it must not complete or redispatch. `AsyncListener.onComplete` is cleanup only. `Connection: close` on the successful SSE response prevents same-socket request reuse.

Set the SSE request's Servlet async timeout to zero; this disables the normal per-request async timeout, but Tomcat can still force `TIMEOUT` during connector shutdown. Do not treat TIMEOUT or `onTimeout` as a proven physical abort. Before web-server destruction, a synchronous `ContextClosedEvent` listener (with async event execution disabled) stops SSE admission, requests external-watchdog ERROR,false teardown for every active SSE handle, and waits for each error-finalization/physical-close operation. It must not be `@Async`; acquire the termination mutex only off callbacks and without wrapper/stream/registry locks. Keep handles registered until abort work joins; marking closed alone must not let shutdown miss a pending dispatch. Do not close unrelated async requests to force a global async count to zero. Forced/abrupt stop before this pre-stop stage is outside the supported close guarantee.

## Authorization timing arithmetic

Revalidate each distinct open-stream principal and session through shared schedules; no per-connection DB poller. The maximum revocation-to-physical-close path is allocated as follows:

| Component | Maximum |
|---|---:|
| Revocation visible to application through abort request, including check scheduling and lease expiry | 2.6 s |
| Abort request to observed actual server socket close | 2.0 s |
| **Revocation visible to application to physical close** | **4.6 s (≤5 s required)** |

Shared principal/session check starts have no more than a 1-second gap. Each DB authorization/session read completes within 1 second or fails closed. A successful check grants an authority lease expiring no later than 2.5 seconds after the check's monotonic start time; a late result cannot renew it. An independent watchdog dispatches a failed check or expired lease to abort within 0.1 seconds. Thus a stale pre-revocation check cannot extend authorization beyond 2.5 seconds plus 0.1 seconds; the end-to-end detection/abort gate is 2.6 seconds. Check cadence/query limits are separately asserted; they do not add another lease interval. If a check fails or a lease expires, stop data writes immediately.

Use monotonic time for check cadence, lease expiry, watchdog dispatch, and close. Measure DB revocation visibility, each check start/completion, lease expiry, abort request, and actual physical close separately. The measured detection ≤2.6s and abort-to-close ≤2s sum to ≤4.6s, within the unchanged 5-second revoke-to-close requirement. Any component miss fails acceptance.

## Backend eligibility and unsupported behavior

Runtime backend eligibility is determined only by server-side capability, not an external topology approval flag. At startup, require the exact `QueueSseHttp11NioProtocol` subclass (Tomcat 11.0.24 `Http11NioProtocol`) and paired `QueueSseHttp11Processor` capture hook. The processor's `service(SocketWrapperBase<?>)` sets a non-inheritable ThreadLocal to the live wrapper around `super.service()` and restores it in `finally`; the exact-route Valve reads that wrapper only for `/events` and attaches a connection-bound handle. For each authenticated/authorized request, require request protocol `HTTP/1.1`, `Connector.getSecure()==false`, protocol-handler `isSSLEnabled()==false`, and a non-null wrapper handle. The effective Servlet/Tomcat response path must also bypass compression/buffering for `text/event-stream`, including native Tomcat compression; verify the active chain at startup and exclude this media type on this route only. If this cannot be proven, the backend is unsupported and an authorized request returns JSON `503` before commitment. The Valve checks transport only; it does not authorize. Spring Security runs normally before the native Servlet. Do not use mutable `Request.isSecure()` or forwarded headers.

Direct native-TLS/secure connectors, HTTP/2/upgrade, non-NIO containers, the uninstrumented stock `Http11NioProtocol`, or missing route capability are unsupported. A plain H1.1 NIO origin behind TLS offload remains server-eligible; it proves only origin-side abort, not client-facing proxy/TLS termination. Test every actual ingress/TLS/proxy path as a separate release gate and block release if its client-facing close/buffering behavior fails or remains unproven; do not turn this external probe into a per-request `503`. No global HTTP timeout/protocol changes, reflection/private-field access, JNI, or broker.

Normal authentication/authorization runs first. For an authorized GET, the native Servlet checks connector/protocol/wrapper eligibility before async start, response commitment, or stream registration. Unsupported server paths return JSON `503` (`application/json`, code `SSE_TRANSPORT_UNSUPPORTED`) with no SSE headers/body; eligible server paths preserve `429` quota behavior. `Connection: close` is set only on the successful `/events` response, and `ERROR,false`/`AsyncListener.onError` are the only forced-close path. Existing REST behavior and oracle assertions are unchanged.

## Static evidence versus required runtime proof

Pinned source evidence establishes mechanism plausibility, not production behavior. The parent also ran an isolated Tomcat prototype; that supplies limited adapter evidence, not Yona endpoint, deadline, topology, or release acceptance:

- Spring 7.0.9 `ResponseBodyEmitter`/`SseEmitter` send/completion share a write lock; `StandardServletAsyncWebRequest` also serializes output and lifecycle state. A blocked `send` can defeat completion-based rescue, which is why the route uses a native Servlet.
- Tomcat 11.0.24 HTTP/1.1 NIO's blocking write timeout resets after progress and is not absolute; connector-wide timeout changes affect unrelated traffic.
- The supported drain observation is the public active-listener `ServletOutputStream.isReady()` path through Coyote `Response.isReady()`/`NB_WRITE_INTEREST`; HTTP/1.1 output `isReady()` is `!hasDataToWrite()`. After successful flush, with no app/Servlet pending bytes/frame, a true readiness query means Tomcat-owned output buffers are empty—not OS TCP send-queue empty, peer ACK, or client receipt. It can be queried from a callback or normal writer path; a new callback is not required. Raw NB_WRITE_INTEREST polling bypasses listener bookkeeping and is not atomic with writes/abort.
- A stored Coyote/Catalina `Response` plus direct `CLOSE_NOW` is rejected: Tomcat's `blockIo` decision can be computed before another thread makes IO forbidden; `AsyncStateMachine.fireOnComplete` can wait on the abort mutex; a Response can be recycled without `onComplete` after executor rejection/socket close. Direct `SocketWrapperBase.close()` is also rejected because it releases/recycles the processor before normal async accounting/decrement.
- The candidate uses the unique per-accepted-connection `SocketWrapperBase` and its normal `setError`/`processSocket(ERROR,false)` path. `SocketProcessorBase` shares the wrapper's public `ReentrantLock`; `ERROR,false` runs on an external thread after callbacks unwind, processes the real connection processor, lets `CoyoteAdapter` issue internal `CLOSE_NOW`, then performs async post-processing/accounting and normal channel close. Only `AsyncListener.onError` completes the already-IO-forbidden error cycle; `WriteListener.onError` only marks state. Connection `close` prevents same-socket future requests.
- HTTP/2 reset remains unsupported. `Request.isSecure()` can be rewritten by `RemoteIpValve`; use backend `Connector.getSecure()` and `AbstractHttp11Protocol.isSSLEnabled()`. Native TLS source checks do not prove client-facing TLS/proxy close.
- Parent's isolated Java 21/Tomcat 11.0.24 `/tmp/yona/queue-plan/SseSocketAbortProbe.java` plus `driverprobe-sse-socket-lifecycle.py` saturated stopped and drip readers at 471,040 bytes. These are not time-aligned from stall/abort start and prove neither 2-second gate. No Yona endpoint/auth/product/topology acceptance is claimed.

## Required probe and release gates

The parent-owned probe must drive the real authenticated `/api/admin/queue/v1/events` route and its production producer/readiness/abort path. It must not substitute a fake generation or alternate endpoint.

1. Use a raw TCP client with a small receive buffer configured before connect; authenticate with a real session, request identity encoding, read headers, initial `reset`, and `Connection: close`, then stop reading. Test direct Tomcat first and repeat through every actual production TLS/proxy topology. Disable compression/buffering only in the explicitly tested topology or record the actual settings.
2. Arm ≤4 KiB reusable pressure comments through the test-only seam, up to the finite attempted-byte budget. Saturation is a prerequisite, not an inferred result: observe persistent pending output and a real `isReady() == false`/container-buffered stall. A small receive buffer or non-reading client alone is insufficient. If the finite budget cannot saturate the tested path, the probe is invalid, not passed. Exercise both zero-reader and drip-reader patterns; keep the next bounded pressure frame pending across the current frame so transient readiness cannot clear/reset its age.
3. Record monotonic timestamps for oldest-output start, DB-visible role/account/session revocation, failed check/lease expiry, `pendingAbort`, wrapper-lock acquisition/release, `setError`, `processSocket(ERROR,false)` entry/return, `AsyncListener.onError`/error `AsyncContext.complete`, actual server socket close, proxy/client-facing termination, registry join/cap release, and client EOF after resumed draining. Match the process-owned server FD by local/remote tuple; `onComplete`, registry removal, and EOF after draining are not physical-close timestamps.
4. Assert (a) abort request no later than oldest-output start +1.5s and actual server socket close no later than start +2.0s total (including watchdog/dispatch/close); (b) drip progress/coalescing never refreshes the oldest age while app output remains; (c) revocation-to-abort ≤2.6s and abort-to-actual-close ≤2s, totaling ≤4.6s (<5s); (d) no application frame after failed authorization; and (e) eventual registration and cap reclamation. Repeat for role revocation, account disablement, and session invalidation. Separately verify each actual proxy/TLS client-facing path before release; origin FD closure alone does not pass that gate.
5. Keep a healthy stream open concurrently; after the initial `reset` has drained, commit at least one additional real queue mutation and verify its `changed` event arrives within 2 seconds while the stream stays open beyond the 1.5-second abort threshold. This covers the normal post-flush readiness path when output is already ready, without requiring another `onWritePossible()` callback. Also verify normal reset/reconnect/heartbeat behavior, unchanged event privacy, slow streams at the 32/2-principal/2-session caps, queue-worker completion, and DB pool use. Preserve existing PR04 REST/auth/oracle assertions exactly; do not replace them with pressure behavior.
6. In an isolated live server instance, issue the same authenticated `/events` request against the uninstrumented stock `Http11NioProtocol` or missing route capability. Do not mock/delete an attribute. Assert JSON `503` (`application/json`) before async start/SSE headers/body; anonymous/non-admin still get `401`/`403`. External proxy/TLS uncertainty is not a request-time `503`.
7. Exercise synchronous `ContextClosedEvent` shutdown before Tomcat stops: stop SSE admission, dispatch external ERROR,false for active SSE handles, await actual socket closure/error finalization, and verify async accounting returns to baseline without closing unrelated async requests. Force a shutdown TIMEOUT separately only to document that it is not the guaranteed abort path.

Until each production ingress/TLS topology passes its actual client-facing close/buffering probe, release remains blocked for that topology.
