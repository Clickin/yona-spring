## Git/Hg 참조 기록 공통화 (2026-10-08)

- 두 listener의 parser→프로젝트 내 이슈 조회→직접 저장을 `CommitIssueReferenceService.record(project, sender, commitId, commitMessage)`로 이동했다. VCS별 commit 선택·ID/message 변환·알림/웹훅 순서와 listener transaction은 유지한다.
- sender는 pusher, created는 이슈 이벤트별 처리 시각이다. 한 메시지 안의 반복 번호만 기존 parser가 합치며, 같은 commit 재처리·여러 ref/bookmark의 추가 이벤트는 그대로 저장한다. draft merge·dedup·SVN·스키마·시각 정책 변경은 없다.
- 추출 전 Git/Hg listener·parser characterization과 추출 후 service·listener·parser·push hook·draft-merge focused 검증이 H2에서 통과했다. 공유 동작 행렬은 `CommitIssueReferenceServiceSpec`, 실제 저장소 연결은 두 listener spec에 둔다.
- 격리된 Spring 앱/H2에 실제 Git HTTP 두 ref 및 Hg HTTP 두 bookmark를 push해 이슈별 2건 저장을 확인했다. 과거 author/commit 시각 대신 pusher/처리 시각, 원래 ID, null oldValue, 다른 프로젝트 참조 0건을 DB와 HTTP 타임라인으로 확인했다. 로컬 웹훅은 Git 1회/Hg 2회이며 ref/bookmark 삭제 후 추가 기록은 없었다. 전체 회귀 결과는 이 focused/runtime 검증과 별도다.
- 전체 H2 회귀: 466 suites, 6,735 tests, 실패/오류 0, skipped 2 (5m55s). 두 skip은 PostgreSQL에서만 실행하는 `PostgresOAuthLobMigrationSpec`이며 다른 DB 전체 통과를 뜻하지 않는다.
